## 二、目标用户与使用场景

### 2.1 目标用户

正在求职的个人用户，自行维护简历与项目材料，从 Boss、拉勾、内推等渠道**手动复制 JD** 到系统。

### 2.2 典型场景

| 场景 | 简述 |
|------|------|
| 整理求职资产 | 上传简历与项目总结 → 知识库问答核对是否覆盖关键经历 |
| 评估新岗位 | 粘贴 JD → 发起分析任务 → 查看匹配报告 → 人工决定是否投递 |
| 面试前准备 | 针对「面试中」岗位生成技术/行为题与复习清单 → 人工练习 |
| 投递后跟进 | 更新投递状态 → 生成 HR 回复建议 → 用户自行在招聘 App 发送 |

## 四、核心用户路径

### 4.1 上传资料 → 知识库

```text
登录 → 个人知识库 → 上传简历/项目文档
→ 查看解析与分块结果 → 发起知识库问答
→ 查看回答与引用来源
```

### 4.2 导入岗位 → 分析 → 报告

```text
岗位导入页录入公司与 JD → 保存并「发起分析」
→ Agent 任务看板查看进度 → 岗位分析报告页查看结构化结果
→ 人工确认后继续或修正
```

### 4.3 匹配 → 话术/面试 → 跟踪

```text
对已分析岗位发起匹配任务 → 匹配分析报告
→ 【人工确认】→ 可选：求职话术生成 / 面试准备
→ 投递跟踪页更新状态（已投递、面试中等）
→ 用户自行在招聘平台完成实际沟通与投递
```

## 五、关键页面说明（一句话）

| 页面 | 目的 |
|------|------|
| 登录页 | 进入系统 |
| 求职工作台首页 | 概览：已分析岗位数、高匹配数、投递/面试中数量、待办建议 |
| 个人知识库 | 上传资料、管理片段、问答与检索 |
| 岗位导入 | 手动录入岗位信息与 JD，发起分析 |
| Agent 任务看板 | 查看任务状态、步骤、Agent、耗时、Token、失败与**人工确认节点** |
| 岗位分析报告 | 展示 JD 结构化分析结果 |
| 匹配分析报告 | 展示匹配度、优劣势、建议与投递建议 |
| 求职话术生成 | 生成打招呼语/求职信/回复建议，**一键复制，不自动发送** |
| 面试准备 | 技术/行为题、回答思路、复习清单 |
| 投递跟踪 | 岗位列表与状态流转、沟通与面试记录 |
| AI 调用日志 | 本系统 AI 调用记录（底座） |
| Token 成本统计 | 本系统 AI 消耗，含多步任务汇总 |
| 系统设置 | 求职偏好、账号设置 |

### 5.1 Agent 任务看板 — 展示要素（阶段四目标）

| 要素 | 说明 |
|------|------|
| 当前任务 | 任务名称、关联岗位 |
| 任务状态 | 进行中 / 待确认 / 成功 / 失败 |
| 执行步骤 | 步骤序号、步骤名称、执行 Agent |
| 步骤耗时 | 每步耗时 |
| 步骤结果 | 摘要或跳转详情 |
| 失败原因 | 失败步骤的错误分类与说明 |
| 人工确认节点 | 明确标注需用户确认的步骤 |
| Token 消耗 | 步骤级或任务级汇总 |
| 模型名称 | 实际调用的模型（来自底座） |

## 六、交互原则

| 原则 | 说明 |
|------|------|
| 人工确认 | 匹配结论、投递建议等关键输出需用户确认后再作为「定稿」 |
| 只生成不发送 | 话术、求职信、HR 回复均为文本建议 + 复制，无「发送」到招聘平台 |
| 状态清晰 | 投递状态枚举统一展示，支持手动更新 |
| 来源可溯 | 知识库问答展示引用片段；报告可关联到底座请求 |
| 任务可见 | 长流程通过任务看板暴露进度，避免黑盒等待 |
| 岗位手动录入 | 不提供「从链接自动抓取 JD」作为主流程 |

### 7.1 包含

| 页面 | 说明 |
|------|------|
| 登录页 | 注册登录 |

### 7.2 工作台首页（第一阶段）

简版：资料完善提醒、知识库入口、最近上传；**不含**岗位统计卡片（阶段二起）。

## 八、本系统第一阶段：不做

1. 岗位导入页、岗位/匹配分析报告
2. Agent 任务看板
3. 求职话术、面试准备、投递跟踪页
4. 招聘平台登录、自动投递、自动抓取 JD
5. 职业画像、多版本简历对比
