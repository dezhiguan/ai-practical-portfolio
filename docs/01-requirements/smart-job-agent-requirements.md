## 二、产品定位与目标用户

### 2.1 产品定位

面向**个人求职与职业成长**场景的智能 Agent 工作台。

通过多 Agent 协作 + 个人知识库（RAG），帮助用户完成岗位分析、经历匹配、求职话术、面试准备与投递进度管理。

### 2.2 目标用户

- 正在求职的技术/产品等知识工作者
- 自行维护简历、项目经历，手动从招聘渠道获取 JD 信息

### 2.3 核心目标

1. 整理并检索个人职业资料
2. 结构化分析目标岗位（JD）
3. 评估个人与岗位的匹配度与差距
4. 生成求职沟通与面试准备内容（人工确认后使用）
5. 管理投递状态与过程沉淀

---

## 三、核心业务流程

```text
1. 上传个人职业资料
2. 解析资料并建立个人知识库
3. 手动导入岗位信息（粘贴 JD）
4. 分析岗位要求（JD 分析 Agent）
5. 检索个人经历（知识库）
6. 生成匹配分析（匹配 Agent）
7. 生成差距分析与优化建议
8. 人工确认关键结论
9. 生成求职沟通内容（话术 Agent / 跟踪 Agent）
10. 生成面试准备内容（面试准备 Agent）
11. 记录投递状态与沟通记录
12. 沉淀求职过程数据
```

**原则：** 岗位信息**用户手动录入**；话术与回复**只生成不自动发送**。

## 五、Agent 角色与职责

> 以下为**输入/输出意图**，非实现规格。

### 5.1 主控 Agent

| 项 | 说明 |
|----|------|
| 输入 | 用户任务意图（如「分析某岗位并给投递建议」）、岗位 ID、上下文 |
| 职责 | 拆解步骤、调度子 Agent、维护任务状态、标识人工确认节点、汇总最终结果 |
| 输出 | 任务执行记录、各步骤结果聚合、下一步建议 |

### 5.2 JD 分析 Agent

| 项 | 说明 |
|----|------|
| 输入 | 岗位名称、公司、原始 JD 文本 |
| 输出 | 岗位级别、核心技能、职责、任职要求、加分项、隐含要求、风险点等结构化报告 |

### 5.3 个人经历匹配 Agent

| 项 | 说明 |
|----|------|
| 输入 | JD 分析结果、个人知识库检索结果 |
| 输出 | 整体匹配度、技能/项目匹配情况、优势与短板、优化建议、投递建议 |

### 5.4 面试准备 Agent

| 项 | 说明 |
|----|------|
| 输入 | JD 分析结果、匹配分析、用户项目经历要点 |
| 输出 | 技术题、项目追问、行为面试题、回答思路、复习清单 |

### 5.5 求职跟踪 Agent

| 项 | 说明 |
|----|------|
| 输入 | 岗位信息、当前状态、用户补充的沟通记录 |
| 输出 | 打招呼语、求职信、HR 回复建议（文本）、阶段总结、下一步建议；更新状态建议 |

**投递状态枚举（参考）：** 感兴趣 → 已投递 → 已查看 → 已沟通 → 面试中 → 已通过 / 已拒绝 → 已归档

## 六、第一阶段工作流（轻量）

本系统**阶段四**才完整实现 Agent 编排；此处描述**目标工作流**，供架构预留。

```text
1. 用户发起任务（如分析岗位）
2. 主控识别任务意图
3. JD 分析 Agent 执行 → 产出结构化 JD 报告
4. 知识库检索个人相关资料
5. 匹配 Agent 执行 → 产出匹配/差距报告
6. 【人工确认节点】用户确认或修正关键结论
7. 按需调度面试准备 / 求职跟踪 Agent
8. 主控汇总最终结果，任务结束
```

**工作流要求（需求层）：**

1. 任务状态可持久化、可查看
2. 每一步可记录输入输出摘要
3. 每一步关联底座调用（模型、Token、耗时）
4. 失败步骤可重试
5. 关键节点必须支持人工确认后再继续或发布建议

## 七、RAG 知识库需求（需求层）

### 7.1 知识库类型

| 类型 | 内容来源 |
|------|----------|
| 个人职业资料 | 简历、自我介绍等 |
| 项目经历 | 项目文档、总结 |
| 技术知识 | 技术笔记、总结 |
| 面试记录 | 历史面试笔记（可选） |
| 岗位信息 | 已保存 JD 与分析结果 |
| 沟通记录 | HR 沟通摘要（用户录入） |

### 7.2 核心能力需求

| 能力 | 说明 |
|------|------|
| 文档解析 | 上传常见格式资料并提取文本 |
| 文本分块 | 适合检索的 chunk 划分 |
| 向量化与存储 | 支持语义检索（实现方式不在本文档） |
| 语义检索 | 根据问题或 JD 要点检索相关片段 |
| 问答 | 基于检索结果生成回答 |
| 引用来源 | 回答需能指向来源片段或文档 |

### 7.3 本系统第一阶段 RAG subset

1. 资料上传与解析
2. 基础分块与存储
3. 基础语义检索与简单问答

### 7.4 后续增强（不在第一阶段）

混合检索、重排序、查询改写、上下文压缩、版本管理、可信度评分等。

| 阶段六：可观测 | Agent 任务看板、步骤与成本查看完善 |

## 九、全局约束

### 9.1 建设原则

1. AI 辅助分析与人机协作，**人工确认**关键结论与对外话术
2. 岗位与 JD **仅用户手动录入**，不自动抓取招聘站
3. 所有大模型调用经**通用 AI 技术底座**

### 9.2 系统负责

资料管理、知识库、岗位分析、匹配分析、话术与面试内容生成、投递状态管理、过程数据沉淀。

### 9.3 系统不负责（红线）

| 序号 | 不做 |
|------|------|
| 1 | 招聘网站自动登录 |
| 2 | 自动投递简历 |
| 3 | 自动抓取岗位 JD |
| 4 | 自动回复 HR |
| 5 | 绕过验证码、风控或平台限制 |

## 十、本系统第一阶段：做什么

> 对应**全项目第三阶段**起步；本系统**阶段一**。

### 10.1 做什么

| 序号 | 范围 |
|------|------|
| 1 | 用户注册、登录与基础资料 |
| 2 | 个人职业资料上传 |
| 3 | 资料解析与文本分块入库 |
| 4 | 基础语义检索与知识库问答 |
| 5 | 接入通用 AI 网关（如问答、解析类调用） |
| 6 | 知识片段列表查看（简化） |

### 10.2 验收方向（业务层）

1. 用户可上传资料并在知识库中检索到相关内容
2. 可完成一次基于检索的问答，且能体现引用来源
3. AI 调用经底座并可查日志
4. 无岗位分析、无 Agent 看板、无自动投递

## 十二、与通用底座的关系

1. **每一次** Agent 步骤中的模型调用均经统一网关
2. 业务类型示例：岗位分析、经历匹配、面试准备、话术生成、文本总结
3. 任务看板需展示：步骤级 Token、模型名称、失败原因（数据来源于底座日志）
4. 业务侧不得独立维护成本统计或降级逻辑
