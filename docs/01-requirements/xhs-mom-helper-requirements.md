## 二、产品定位与目标用户

### 2.1 产品定位

面向**个人内容创作者**（如母婴、育儿类博主）的 AI 辅助内容运营工作台。

帮助用户完成从**素材管理 → 内容生成 → 草稿与排期 → 发布辅助 → 数据复盘**的运营闭环。

### 2.2 目标用户

- 个人小红书创作者，自行拍摄素材、撰写或辅助生成文案、人工发布
- 单账号运营为主（多账号、团队协作为后续扩展）

### 2.3 核心目标

1. 沉淀可复用素材资产
2. AI 辅助生成标题、正文、标签（人工确认）
3. 管理草稿与发布计划
4. 导出发布包，由用户在小红书 App 内人工发布
5. 录入发布数据并形成复盘建议

---

## 三、核心业务流程

```text
1. 上传素材
2. 素材分类与标签管理
3. 选择素材与内容风格
4. 生成标题、正文、标签（经 AI 底座）
5. 人工编辑与确认
6. 保存草稿
7. 加入内容日历排期
8. 导出发布包
9. 用户在小红书平台人工发布
10. 录入发布数据（浏览、点赞、收藏等）
11. AI 复盘分析（经 AI 底座）
12. 沉淀内容资产与经验
```

**原则：** AI 辅助生成与分析，**关键动作由人工执行**（尤其发布环节）。

## 四、功能模块清单

| 模块 | 职责摘要 |
|------|----------|
| 用户与账号 | 注册登录、创作者资料与基础设置 |
| 素材库 | 图片/视频上传、分类、标签、搜索与使用记录 |
| AI 内容生成 | 选素材、主题、风格，生成标题/正文/标签，编辑与存草稿 |
| 草稿管理 | 草稿 CRUD、状态流转、关联素材、加入日历 |
| 内容日历 | 月/周视图、排期、提醒；**不自动发布** |
| 发布包导出 | 文案复制、素材下载、检查清单、元数据 |
| 发布数据复盘 | 手动录入数据、指标计算、AI 优化建议 |
| AI 成本查看 | 复用底座：调用记录、Token、成本（本系统维度） |

## 五、模块职责与边界

### 5.1 用户与账号

- 提供用户身份与创作者基础资料配置
- 不负责小红书平台账号绑定、OAuth、自动登录

### 5.2 素材库

- 管理用户上传的图片、视频及元数据（分类、标签）
- 记录素材被哪些草稿/内容使用
- 不负责从小红书抓取他人内容或平台素材

### 5.3 AI 内容生成

- 根据素材、主题、风格调用底座生成标题、正文、标签
- 支持重新生成与人工编辑后保存草稿
- 支持的内容风格示例：可爱风、种草风、育儿干货、日常分享、搞笑反差、妈妈/爸爸视角等
- **所有生成请求必须经通用 AI 技术底座**，并留下业务类型标识供统计

### 5.4 草稿管理

- 草稿状态：草稿 → 待发布 → 已排期 → 已发布 → 已归档
- 关联素材、支持复制文案、可加入内容日历
- 不代替用户在平台侧创建或发布笔记

### 5.5 内容日历

- 规划发布时间与关联草稿，支持提醒
- **仅计划与提醒，不执行自动发布**

### 5.6 发布包导出

- 聚合标题、正文、标签、素材文件、检查清单
- 用户通过复制文案、下载素材后，在小红书 App **人工完成发布**

### 5.7 发布数据复盘

- 用户**手动录入**浏览量、点赞、收藏、评论、涨粉等
- 系统计算互动指标，可调用 AI 生成表现分析与后续建议
- 不负责自动抓取平台后台数据

### 5.8 AI 成本查看

- 展示本系统相关的 AI 调用与成本（依赖底座数据）
- 不在业务侧重复实现统计逻辑

## 六、全局约束

### 6.1 建设原则

1. **AI 辅助，人工确认**：生成内容需用户确认后再使用
2. **先闭环，后扩展**：优先打通素材 → 生成 → 草稿 → 排期 → 导出 → 复盘主路径
3. **统一经底座调用 AI**：业务不直连模型 API

### 6.2 系统负责

| 类别 | 内容 |
|------|------|
| 内容生产辅助 | 素材管理、AI 生成、草稿、排期、发布包 |
| 发布后运营 | 数据录入、指标计算、复盘建议 |
| 资产沉淀 | 素材、草稿、历史复盘记录 |

### 6.3 系统不负责（红线）

| 序号 | 不做 |
|------|------|
| 1 | 小红书自动登录 |
| 2 | 自动发布笔记 |
| 3 | 自动抓取评论、私信、平台数据 |
| 4 | 自动回复用户 |
| 5 | 绕过验证码、风控或平台规则 |

## 七、非功能需求（轻量）

| 类别 | 要求 |
|------|------|
| 素材安全 | 用户仅能访问本人素材；上传需基础格式与大小约束 |
| 可追溯 | 草稿与 AI 生成结果可关联到底座请求编号（展示层） |
| 状态一致 | 草稿状态流转符合业务规则，避免已发布仍显示可排期等矛盾 |
| 可用性 | 发布包导出步骤清晰，降低人工发布漏项 |

## 八、本系统分阶段轮廓

| 本系统阶段 | 目标（一句话） |
|------------|----------------|
| 阶段一：基础能力 | 用户、素材上传与管理、AI 基础调用与日志查看 |
| 阶段二：内容生成 | 标题/正文/标签生成、风格选择、编辑存草稿 |
| 阶段三：内容管理 | 草稿箱、状态流转、内容日历与排期提醒 |
| 阶段四：发布辅助 | 发布包导出、检查清单、发布状态更新 |
| 阶段五：复盘能力 | 发布数据录入、指标计算、AI 复盘建议 |
| 阶段六：可观测 | 本系统维度的 AI 日志与成本查看完善 |

## 九、本系统第一阶段：做什么

> 对应**全项目第二阶段**起步；本系统**阶段一：基础能力**。

### 9.1 做什么

| 序号 | 范围 |
|------|------|
| 1 | 用户注册、登录与基础资料 |
| 2 | 图片/视频素材上传与列表、基础分类 |
| 3 | 素材预览与简单筛选 |
| 4 | 接入通用 AI 网关，完成至少一种生成类调用的端到端验证 |
| 5 | 可查看与本系统相关的 AI 调用日志（依赖底座） |

### 9.2 验收方向（业务层）

1. 用户可登录并上传、浏览自己的素材
2. 可通过工作台发起一次经底座的 AI 调用并看到结果与日志关联
3. 未出现任何自动发布或平台登录能力

## 十、本系统第一阶段：不做什么

| 序号 | 不做 |
|------|------|
| 1 | 完整标题/正文/标签生成流程与风格库（属阶段二） |
| 2 | 草稿箱、内容日历、发布包导出（属阶段三、四） |
| 3 | 发布数据录入与 AI 复盘（属阶段五） |
| 4 | 自动发布、登录、抓取、私信 |
| 5 | 多平台适配、选题库、团队协作、Prompt 模板管理 |

## 十一、与通用底座的关系

### 11.1 依赖能力

1. 统一 AI 网关
2. 模型路由（内容生成、标题生成、标签生成、内容复盘等业务类型）
3. 调用日志、Token 与成本统计
4. 失败追踪与降级

### 11.2 本系统需传递的标识

每次 AI 调用应携带：

- **项目标识**：小红书工作台
- **业务类型**：如内容生成、标题生成、标签生成、内容复盘
- **用户标识**：用于成本与日志关联

### 11.3 禁止事项

业务代码不得绕过底座直接调用模型供应商。
