### 1.1 文档定位

本文档将通用 AI 技术底座从 0 到 1 的建设工作拆解为**可单独执行的小任务**，供按序一步一步开发。

每个任务包含：**目标、范围、输入、输出、验收标准**。

### 1.3 编写约束

1. 不写代码、不写具体实现细节（类名、框架、表字段等）
2. 不涉及小红书、求职 Agent 的业务功能开发
3. 任务粒度控制在「单次会话或半天内可完成并验收」
4. 任务之间有明确依赖，须按推荐顺序执行

## 三、任务清单

### 阶段 A：工程与约定

---

#### T-001 模块工程骨架初始化

| 项 | 内容 |
|----|------|
| **目标** | 建立 `ai-common-infra` 可独立开发与运行的最小工程骨架 |
| **范围** | 模块目录、构建配置占位、环境配置占位、本地启动入口占位；不实现业务逻辑 |
| **输入** | 项目根目录规范、[development-plan.md](./development-plan.md) 任务一 |
| **输出** | 可构建、可启动（空服务）的模块骨架；README 或模块内说明列出子目录职责 |
| **验收标准** | 1. 目录结构清晰，与后续逻辑模块可对应<br>2. 本地可执行一次「空启动」<br>3. 不含小红书/求职 Agent 代码 |

---

#### T-002 统一公共约定（返回、异常、追踪）

| 项 | 内容 |
|----|------|
| **目标** | 确定底座对内、对调用方的统一错误表达与请求追踪约定 |
| **范围** | 成功/失败返回结构语义；业务异常与系统异常划分；请求追踪标识如何贯穿网关与日志 |
| **输入** | 需求 4.1 响应语义；需求 4.4 失败类型 |
| **输出** | 约定说明（可写入架构文档或模块内 ADR）；各后续任务遵循该约定 |
| **验收标准** | 1. 文档化成功/失败响应最小字段集<br>2. 明确「请求编号」与「追踪标识」关系<br>3. 敏感信息不得进入对调用方可见的错误详情 |

---

#### T-003 配置与环境管理约定

| 项 | 内容 |
|----|------|
| **目标** | 确定模型密钥、路由规则、限流阈值等配置的加载方式与分环境原则 |
| **范围** | 配置文件组织、环境变量命名原则、敏感项不入库；不写具体配置项代码 |
| **输入** | T-001 工程骨架；需求 4.8、4.9 |
| **输出** | 配置分层说明；示例配置模板（无真实密钥） |
| **验收标准** | 1. 开发/本地/生产配置边界清晰<br>2. 密钥仅通过安全渠道注入<br>3. 后续 T-008～T-010 可在此基础上落地 |

---

### 阶段 B：核心语义与配置

---

#### T-004 统一 AI 调用请求语义

| 项 | 内容 |
|----|------|
| **目标** | 固化业务方向网关发起调用时必须提供的请求要素 |
| **范围** | 业务类型、用户标识（可选）、项目标识（可选）、输入内容、扩展参数；必填/可选规则 |
| **输入** | 需求 4.1.2、4.1.4 |
| **输出** | 请求语义说明；非法/缺失必填项时的失败行为定义 |
| **验收标准** | 1. 覆盖需求表中全部请求要素<br>2. 明确业务类型为必填<br>3. 项目标识可区分「底座自测 / 未来业务项目」 |

---

#### T-005 统一 AI 调用响应语义

| 项 | 内容 |
|----|------|
| **目标** | 固化网关向调用方返回的响应要素及状态取值 |
| **范围** | 请求编号、调用状态（成功/失败/降级成功）、输出内容、Token、估算成本、耗时、实际模型、失败信息 |
| **输入** | 需求 4.1.3；T-002 公共约定 |
| **输出** | 响应语义说明；各状态含义与调用方处理建议 |
| **验收标准** | 1. 覆盖需求 4.1.3 全部要素<br>2. 「降级成功」与「普通成功」可区分<br>3. 与 T-004 请求语义可一一对应做一次完整调用描述 |

---

#### T-006 业务类型与项目标识注册表

| 项 | 内容 |
|----|------|
| **目标** | 建立第一阶段支持的业务类型与项目标识清单，供路由与统计使用 |
| **范围** | 登记需求 4.1.4 示例类型 + 「底座自测」类型；项目标识至少支持：底座、小红书（预留）、求职 Agent（预留） |
| **输入** | 需求 4.1.4、4.6.2 统计维度 |
| **输出** | 业务类型/项目标识登记表；未知类型的拒绝策略 |
| **验收标准** | 1. 每种业务类型可独立配置路由（为 T-008 准备）<br>2. 未知业务类型调用被拒绝且有明确原因<br>3. 满足 AC-7 对项目维度的数据要求 |

---

#### T-007 失败类型与调用状态枚举

| 项 | 内容 |
|----|------|
| **目标** | 统一失败分类与调用状态，供日志、统计、重试、降级共用 |
| **范围** | 失败类型 8 类（需求 4.4.2）；调用状态与失败类型映射关系；哪些类型可重试/可降级（原则级） |
| **输入** | 需求 4.4、4.5、4.3 |
| **输出** | 失败类型与状态对照表；与供应商原始错误的归类原则（不写代码映射表） |
| **验收标准** | 1. 8 种失败类型齐全<br>2. 认证/内容安全/参数错误标记为不可重试、不可降级<br>3. 网络/超时/限流/部分模型内部错误标记为可重试或可走降级 |

---

#### T-008 模型与供应商登记配置

| 项 | 内容 |
|----|------|
| **目标** | 配置第一阶段接入的模型供应商与模型清单 |
| **范围** | 至少 1 个供应商、2 个逻辑模型（用于主备/降级验证）；模型显示名、供应商侧模型 ID、超时默认值 |
| **输入** | T-003 配置约定；T-011 适配边界 |
| **输出** | 模型登记表；供应商连接参数说明（占位） |
| **验收标准** | 1. 至少 2 个模型可用于主备<br>2. 模型名称在日志与响应中一致<br>3. 未登记模型不可被路由选中 |

---

#### T-009 按业务类型的路由规则配置

| 项 | 内容 |
|----|------|
| **目标** | 为每个业务类型配置主模型与备用模型顺序 |
| **范围** | 静态配置：业务类型 → 主模型 → 备用模型列表；低成本优先策略体现在「简单业务类型默认低成本模型」 |
| **输入** | 需求 4.2；T-006、T-008 |
| **输出** | 路由规则配置表；默认规则与示例业务类型的映射 |
| **验收标准** | 1. 每个已登记业务类型有且仅有一条主路由规则<br>2. 至少一个业务类型配置 2 个以上备用模型<br>3. 路由结果可记录「计划模型」（为 T-023 准备） |

---

#### T-010 模型 Token 单价配置

| 项 | 内容 |
|----|------|
| **目标** | 为成本估算提供模型级单价配置 |
| **范围** | 每模型输入/输出 Token 单价；无法获取 Token 时的处理标记 |
| **输入** | 需求 4.6.4；T-008 |
| **输出** | 单价配置表；估算成本计算公式说明（需求层） |
| **验收标准** | 1. 已登记模型均有单价或明确「按次估算」规则<br>2. 估算结果在响应与日志中标注为估算值<br>3. 为 T-030 成本计算提供输入 |

### 阶段 C：供应商适配层

---

#### T-011 供应商适配层边界定义

| 项 | 内容 |
|----|------|
| **目标** | 定义底座与具体模型供应商之间的适配边界，屏蔽供应商差异 |
| **范围** | 适配层入参/出参语义；需屏蔽的差异点（鉴权、请求体、响应体、Token 字段、错误码）；适配层不负责路由、日志、重试 |
| **输入** | 需求 4.1.1；T-004、T-005 |
| **输出** | 适配层职责说明；与网关层的调用契约 |
| **验收标准** | 1. 网关仅依赖适配层统一语义，不感知供应商 API 细节<br>2. 适配层输出可被统一映射到 T-007 失败类型<br>3. 文档可供 T-012 实现对照 |

---

#### T-012 首个供应商适配实现

| 项 | 内容 |
|----|------|
| **目标** | 完成第一个模型供应商的连通与最小调用闭环 |
| **范围** | 单次文本生成调用；返回内容与 Token（若供应商提供）；错误映射到统一失败语义 |
| **输入** | T-011；T-008；有效 API 密钥（环境配置） |
| **输出** | 可对单一登记模型完成一次真实调用的适配能力 |
| **验收标准** | 1. 使用登记模型之一可成功返回内容<br>2. 故意错误密钥时归类为认证错误<br>3. 超时场景可归类为请求超时（可用模拟或短超时验证） |

---

#### T-013 第二模型登记与适配复用验证

| 项 | 内容 |
|----|------|
| **目标** | 验证同一供应商下第二模型或第二供应商可复用适配模式 |
| **范围** | 在 T-012 基础上增加第二个逻辑模型；不重复建设网关逻辑 |
| **输入** | T-012；T-008 |
| **输出** | 两个模型均可通过适配层调用 |
| **验收标准** | 1. 两个模型调用均返回统一响应语义<br>2. 日志中「实际模型」字段可区分二者<br>3. 为降级链路的多模型尝试做准备 |

### 阶段 D：网关最小主链路

---

#### T-014 全局请求编号生成

| 项 | 内容 |
|----|------|
| **目标** | 为每次 AI 调用生成全局唯一请求编号，贯穿响应与日志 |
| **范围** | 编号生成规则；与追踪标识关系；并发下唯一性 |
| **输入** | T-002；需求 4.7.2 |
| **输出** | 请求编号生成能力；编号格式说明 |
| **验收标准** | 1. 任意两次调用编号不同<br>2. 响应中始终携带请求编号<br>3. 支持通过编号反查单次调用（为 T-022 准备） |

---

#### T-015 网关最小调用链路（无路由、无降级）

| 项 | 内容 |
|----|------|
| **目标** | 打通「接收请求 → 固定模型 → 适配调用 → 返回响应」的最小路径 |
| **范围** | 校验 T-004 必填项；写死或配置单一默认模型；记录耗时；不含路由、重试、降级、持久化 |
| **输入** | T-004、T-005、T-012、T-014 |
| **输出** | 可通过网关完成一次端到端 AI 调用的能力 |
| **验收标准** | 1. 合法请求返回成功响应且含请求编号、输出、耗时<br>2. 非法业务类型或缺必填项返回参数类失败<br>3. 调用方不直接接触供应商 API |

---

#### T-016 网关调用耗时统计

| 项 | 内容 |
|----|------|
| **目标** | 在网关层统计单次调用端到端耗时并写入响应 |
| **范围** | 从接收请求到获得最终结果的时间；含适配层等待，不含调用方网络 |
| **输入** | T-015 |
| **输出** | 响应中稳定的耗时字段；耗时统计口径说明 |
| **验收标准** | 1. 成功与失败响应均含耗时（失败时可为部分耗时）<br>2. 耗时单位为毫秒且为正整数<br>3. 满足 AC-2 对耗时字段的要求 |

---

#### T-017 网关入参校验与快速失败

| 项 | 内容 |
|----|------|
| **目标** | 在进入适配层前完成请求校验，减少无效供应商调用 |
| **范围** | 业务类型合法性、项目标识合法性、输入内容非空等；校验失败归类为参数错误 |
| **输入** | T-004、T-006、T-007 |
| **输出** | 校验规则清单；校验失败时的统一响应 |
| **验收标准** | 1. 未登记业务类型不发起供应商调用<br>2. 校验失败产生可读失败信息且不泄露内部配置<br>3. 校验失败计入后续日志（T-020） |

---

### 阶段 E：调用日志与请求追溯

---

#### T-018 调用日志数据模型与存储选型

| 项 | 内容 |
|----|------|
| **目标** | 确定单次 AI 调用日志的持久化方案与字段集合 |
| **范围** | 覆盖需求 4.7.2 全部字段；成功/失败/降级成功均记录；存储介质选型（架构文档可细化） |
| **输入** | 需求 4.7；T-007 |
| **输出** | 调用日志字段说明；存储方案决策记录 |
| **验收标准** | 1. 字段集与需求 4.7.2 一一对应<br>2. 支持按请求编号唯一查询<br>3. 敏感密钥不写入日志详情 |

---

#### T-019 调用日志写入（成功路径）

| 项 | 内容 |
|----|------|
| **目标** | 每次成功调用（含降级成功）完成后写入完整日志 |
| **范围** | 在 T-015 链路上增加写日志；含计划模型、实际模型、Token、成本、耗时、重试次数初值 0 |
