# AI Practical Portfolio

## 1. 项目简介

本项目用于建设两个真实可用的 AI 应用系统，并沉淀一套通用 AI 应用基础能力。

项目整体包含三个部分：

1. 通用 AI 技术底座
2. 小红书内容运营工作台
3. 智能求职 Agent 工作台

整体建设目标是：先沉淀统一 AI 基础设施，再基于该基础设施建设两个业务系统，最终形成一套可复用、可扩展、可持续演进的 AI 应用工程体系。

## 4. 建设顺序

项目按以下顺序推进。

### 4.1 第一阶段：通用 AI 技术底座

优先完成：

1. 统一 AI 网关
2. 模型路由
3. 调用日志
4. Token 统计
5. 成本统计
6. 失败追踪
7. 模型降级

目标：

形成两个业务系统共用的 AI 基础能力，避免重复建设模型调用、日志记录、成本统计和异常处理能力。

---

### 4.2 第二阶段：小红书内容运营工作台

优先完成：

1. 素材上传
2. 素材管理
3. AI 内容生成
4. 草稿箱
5. 内容日历
6. 发布包导出
7. 发布数据复盘

目标：

完成从素材管理、内容生成、内容排期、发布辅助到数据复盘的完整内容运营闭环。

---

### 4.3 第三阶段：智能求职 Agent 工作台

优先完成：

1. 个人资料上传
2. 个人知识库
3. 岗位导入
4. JD 分析
5. 匹配分析
6. Agent 工作流
7. 面试准备
8. 投递跟踪

目标：

完成从个人资料管理、岗位分析、经历匹配、面试准备到投递进度管理的完整求职辅助闭环。

---

### 4.4 第四阶段：能力增强

后续增强方向：

1. Prompt 模板管理
2. 多平台内容适配
3. 选题库
4. 职业画像
5. 面试复盘
6. RAG 混合检索
7. Agent 可观测
8. 动态模型路由
9. 成本策略优化

## 7. 开发协作规范

开发过程中遵循以下原则：

1. 每次只开发一个明确模块
2. 每个模块需要有清晰边界
3. 所有 AI 调用必须经过统一 AI 网关
4. 业务模块不直接调用具体模型 API
5. 每个阶段完成后需要更新开发进度文档
6. 重要决策需要记录到决策日志
7. 中断后必须先阅读进度文档，再继续开发
